# Mini NPU Simulator 아키텍처

기능과 완료 조건은 `feature.md`, 미션 원문은 `mission.md`를 기준으로 한다.
이 문서는 구현된 데이터 구조, 모듈의 책임, 호출 흐름을 정의한다.

## 설계 원칙

- 세 모드는 동일한 `Pattern`과 `Filter`를 사용한다.
- `Pattern`은 입력 배열뿐 아니라 필터별 점수, 판정, expected 비교 결과를 소유한다.
- MAC 계산과 점수 비교는 계산 함수가 수행하고, 분석 함수가 결과를 `Pattern`에 기록한다.
- 모드별 함수는 입력·출력과 오류 복구, 실행 순서를 담당한다.
- 크기별 반복 성능 측정 결과는 `Pattern`의 판정 결과와 별도로 관리한다.
- 객체의 생성자에는 입력 데이터만 전달한다. 계산 결과는 생성 시 초기화하고 분석 후 채운다.
- Python 3.11에서 개발하되 Python 3.8 이상에서 실행할 수 있게 구현한다.
  타입 표기는 `typing`의 `List`, `Dict`, `Optional`, `Sequence`를 사용하고, Python 3.9 이상의 내장 제네릭이나
  Python 3.10 이상의 `T | None` 표기를 사용하지 않는다. 사용하는 표준 라이브러리 API도 Python 3.8에서 지원해야 한다.

## 데이터 구조

### Pattern

생성자 계약은 `Pattern(n, array, expected=None)` 하나로 통일한다.

| 필드 | 타입 | 초기값 또는 의미 |
| --- | --- | --- |
| `n` | `int` | 배열의 한 변 크기 |
| `array` | `List[List[float]]` | 검증한 입력 패턴의 원소를 float로 변환해 복사한 배열 |
| `expected` | `Optional[str]` | 모드 1은 `None`, 모드 2는 정규화된 `Cross` 또는 `X` |
| `scores` | `Dict[str, float]` | 생성 시 빈 딕셔너리, 분석 후 필터 라벨별 점수 |
| `prediction` | `Optional[str]` | 생성 시 `None`, 분석 후 선택된 필터 라벨 또는 `UNDECIDED` |
| `passed` | `Optional[bool]` | 생성 시 `None`. 모드 1은 비교하지 않아 `None`, 모드 2는 PASS/FAIL에 대응하는 참/거짓 |
| `failure_reason` | `Optional[str]` | 생성 시 `None`, 모드 2에서 실패하면 원인 요약 |

- `scores`는 객체마다 새 딕셔너리로 생성한다. 여러 Pattern이 기본 딕셔너리를 공유하지 않는다.
- 모드 1은 `Pattern(3, array)`로 생성하고, `scores`의 키는 `A`, `B`를 사용한다.
- 모드 2는 `Pattern(n, array, expected=normalized_expected)`로 생성하고,
  `scores`의 키는 `Cross`, `X`를 사용한다.
- JSON 모드에서 expected는 필수다. 생성자 기본값이 `None`이어도 누락된 expected를 정상 케이스로 허용하지 않는다.
- `prediction=None`은 아직 계산하지 않은 상태이며, `UNDECIDED`는 계산을 완료한 동점 결과다.
- 모드 1에서 `UNDECIDED`는 콘솔에 `판정 불가`로 표시한다.
- 모드 2의 케이스 ID는 `Dict[str, Pattern]`의 키로 보관한다.
  예: `patterns["size_5_1"]`에서 해당 Pattern과 그 결과를 조회한다.
- 원본 항목이 잘못되어 Pattern을 생성할 수 없는 경우에는 모드 2가 케이스 ID와 실패 사유를 직접 기록한다.
- 호출당 `op_count`는 N²이며, 케이스 전체의 MAC 횟수는 N²에 비교하는 필터 수를 곱해 산출한다.
  두 값 모두 Pattern의 별도 변경 가능한 필드로 중복 저장하지 않는다.

### Filter

생성자 계약은 `Filter(n, array, label)`이다.

| 필드 | 타입 | 의미 |
| --- | --- | --- |
| `n` | `int` | 배열의 한 변 크기 |
| `array` | `List[List[float]]` | 검증한 필터의 원소를 float로 변환해 복사한 배열 |
| `label` | `str` | 모드 1은 `A` 또는 `B`, 모드 2는 `Cross` 또는 `X` |

JSON 필터는 `Dict[int, Dict[str, Filter]]`로 보관한다.
예: `filters[5]["Cross"]`는 정규화된 5×5 Cross 필터다.
수동 입력 필터 A/B가 실제 Cross/X 모양인지 추측하거나 검증하지 않는다.

### 성능 측정 결과

- 패턴·필터 조합별 측정 결과는 `n`, `filter_label`, `repeats`, `average_ms`, `op_count`를 담은 딕셔너리로 표현한다.
- `op_count`는 필터 하나에 대한 N²이며, Pattern을 두 필터로 판정하는 2N²와 구분한다.
- 모드 1은 입력 패턴과 A/B 두 조합, 모드 2는 모든 유효 패턴과 Cross/X 조합의 결과를 모은다.
- 크기별 평균은 `sum(average_ms * repeats) / sum(repeats)`로 집계한다.
  `print_benchmark_table()`은 같은 크기의 결과를 모아 방식별 평균 ms와 배속, N², 방식별 호출 수와 데이터 출처를 한 행에 출력한다.
- 모드 1은 3×3 요약 한 행, 모드 2는 필수 네 크기의 요약 행을 출력한다.
  추가 크기에 유효한 패턴·필터 조합이 있으면 해당 크기도 행을 추가한다.
- 결과 객체를 위한 별도 클래스는 필수로 도입하지 않는다.

## 공통 함수 계약

아래 함수는 모드별 처리에서 사용하는 공통 계약이다.

| 함수 | 입력 | 반환 및 변경 사항 |
| --- | --- | --- |
| `validate_matrix(n, array)` | 크기와 배열 | 양의 정수 N, 행·열 수, int/float 원소 검증. bool·NaN·inf·float 범위를 벗어난 정수는 거부. 성공 시 `None`, 실패 시 사유를 담은 `ValueError` |
| `validate_pair(pattern, filter)` | 패턴과 필터 | 각 배열과 두 크기를 검증. 실패 시 `ValueError` |
| `parse_pattern_key(case_id)` | `size_{N}_{idx}` 키 | 양의 정수 N 반환. idx는 0 이상의 숫자 문자열이며 선행 0을 허용. N은 정수 변환해 정규형 `size_N` 필터와 연결. 잘못된 형식은 `ValueError` |
| `normalize_expected(value)` | JSON expected | `+`를 `Cross`, `x`를 `X`로 변환. 미지원 값은 `ValueError` |
| `normalize_filter_label(value)` | JSON 필터 키 | `cross`를 `Cross`, `x`를 `X`로 변환. 미지원 값은 `ValueError` |
| `mac(pattern, filter)` | 검증된 패턴과 필터 | `0.0`부터 행 우선 반복문과 `+=`로 계산한 점수 반환. 유한수의 곱셈·누적이 float 범위를 벗어나면 `ValueError`. Pattern의 기존 결과는 변경하지 않음 |
| `compare_mac_scores(scores, epsilon=1e-9)` | 라벨이 서로 다른 두 필터의 점수 | 선택한 라벨 또는 `UNDECIDED` 반환 |
| `evaluate_pattern(pattern, filters, epsilon=1e-9)` | Pattern과 `Sequence[Filter]`에 담긴 서로 다른 라벨의 필터 두 개 | 검증·MAC·비교를 수행하고 Pattern의 결과 필드에 기록. 반환값은 `None` |
| `benchmark_mac(pattern, filter, repeats=10)` | 검증된 패턴·필터 한 조합과 10 이상의 반복 횟수 | 조합별 평균 시간과 N²를 담은 측정 결과 반환. Pattern의 판정 결과는 변경하지 않음 |
| `benchmark_mac_layouts(pattern, filter, repeats=10)` | 같은 패턴·필터와 반복 횟수 | 두 배열을 행 우선으로 펼친 뒤 점수 일치를 확인한다. 기존 결과 필드에 1차원 호출당 평균 `flat_average_ms`를 추가한다. |
| `print_benchmark_table(results, fallback_sizes=(), *, source_label="입력")` | 조합별 측정 결과, 대체 데이터 크기, 출처 | 두 방식 각각의 가중 평균, 배속, N², 방식별 호출 수와 출처를 표시한다. |
| `mode1.main()` | 콘솔 입력 | 입력·분석·성능 출력 완료 후 `None` 반환 |
| `mode2.main()` | `data/data.json` | 분석·집계를 완료하면 `True`, 파일 전체 오류로 메뉴 복귀가 필요하면 `False` |

JSON 구조 검증은 딕셔너리·배열 등의 타입을 먼저 확인하고 키와 원소를 읽는다.
키 누락, 잘못된 중첩 구조·타입·라벨·크기는 원인을 담은 `ValueError`로 전달하며,
필터 그룹 또는 케이스를 처리하는 모드 2의 경계에서 포착한다.
잘못된 입력으로 `KeyError`, `TypeError`, `AttributeError`가 그대로 전파되지 않도록 한다.

### 입력 위치별 라벨 정규화 (#12)

`src/validation.py`의 `normalize_expected()`는 정답의 `+`/`x`를,
`normalize_filter_label()`은 필터 키의 `cross`/`x`를 각각 `Cross`/`X`로 변환한다.
입력 위치마다 허용하는 원본 표기가 다르므로 함수를 분리했으며, 두 함수 모두 미지원 값에 `ValueError`를 발생시킨다.
이 방식은 정답과 필터 키의 검증 범위·오류 메시지를 명확히 하고 다른 위치의 표기를 잘못 허용하는 일을 막는다.
변환 규칙을 로더 밖에서 독립적으로 테스트할 수 있고, 판정과 출력은 JSON의 표기법을 알 필요 없이 같은 표준 라벨을 사용한다.
반면 표준 라벨을 추가할 때 두 함수와 모델의 허용 목록·테스트를 함께 관리해야 하므로 한쪽 변경을 빠뜨릴 수 있다.
JSON 표기는 공백 제거·대소문자 통일을 자동 적용하지 않는다. 모드 1의 대소문자 무관 Cross/X 생성 명령은
`mode1._read_matrix()`에서 처리하는 별도 입력 기능이다.

### 새 표기와 새 분류 대상의 확장 범위 (#18)

새 표기(alias)를 기존 `Cross`/`X`로 연결하는 변경은 해당 입력 위치의 정규화 함수와 허용·거부 테스트를 중심으로 한다.
새로운 모양을 별도 분류 대상으로 추가하거나 세 번째 필터를 비교하려면 표준 라벨과 두 필터 전용 계약도 함께 검토해야 한다.
새 분류 대상을 도입할 때는 다음 순서로 확인한다.

- [ ] **정규화:** 입력 위치별 별칭과 표준 라벨을 정한다. 새 표준 라벨이면 `models.Pattern.expected`와
  `Filter.label`의 허용 목록, `mode2._read_filter_pair()`의 정확한 `{Cross, X}` 집합 검사도 변경한다.
  필터 키 별칭들이 같은 표준 라벨로 겹칠 때는 덮어쓰기·거부 등 처리 정책을 먼저 정한다.
- [ ] **판정:** `calculator.evaluate_pattern()`과 `compare_mac_scores()`의 두 필터·두 점수 제한 및 라벨 중복 검사를 검토한다.
  세 필터라면 최고점과 차점의 차이로 epsilon 동점을 판정할지, 최고점 동률·전체 동점·차이가 정확히 epsilon인 경우를
  어떻게 처리할지 정한다. 하위 두 점수의 동점만으로 유일한 최고점을 판정 불가로 만들지 않는지도 확인한다.
- [ ] **출력과 측정:** `mode2`의 Cross/X 고정 점수 출력·로드 안내와 대체 필터를 변경하고,
  수동·생성 모드에도 새 종류를 제공한다면 `mode1`의 A/B 입력·출력과 `bonus`의 생성 필터 구성도 맞춘다.
  생성기까지 확장하면 `patterns.generate_patterns()`의 Cross/X 두 배열 반환 계약과 호출부도 함께 검토한다.
  `mac()`과 `benchmark_mac_layouts()`는 한 패턴·필터 조합을 그대로 재사용할 수 있고, `reporting`의 크기별 가중 집계도 라벨에 의존하지 않는다.
  모든 유효 조합이 전달되는지 확인한다. 필터가 세 개면 호출당 N²는 같지만 판정당 3N²,
  유효 패턴 P개·반복 R회에 대한 방식별 호출 수는 `P × 3 × R`이 된다.
- [ ] **테스트와 기대 결과:** 별칭 허용·거부, 새 라벨의 모델·JSON 검증, 세 점수의 최고점·동점·epsilon 경계,
  케이스별 점수·PASS/FAIL·실패 사유와 전체 집계, 모든 필터의 2D/1D 측정을 검증한다.
  기존 두 필터 경로의 예제와 6/3/3 결과는 회귀 검증하고, 세 번째 필터가 적용되는 데이터의 기대 판정·집계는 다시 계산한다.
  관련 명세·README와 Python 3.8/3.11 테스트도 함께 갱신한다.

### 분석 결과 기록

`evaluate_pattern()`은 다음 순서로 동작한다.

1. 기존 `scores`, `prediction`, `passed`, `failure_reason`을 초기화한다.
2. 필터가 두 개이고 라벨이 서로 다른지, 패턴과 각 필터가 올바른 크기인지 검증한다.
3. 각 필터의 `mac()` 결과를 임시 딕셔너리에 계산한다.
4. `abs(score_a - score_b) < epsilon`이면 `UNDECIDED`, 그 외에는 큰 점수의 라벨을 선택한다.
5. 계산이 모두 성공하면 `pattern.scores`와 `pattern.prediction`에 기록한다.
6. expected가 있으면 비교해 `pattern.passed`를 설정한다. 동점 또는 expected 불일치 시 사유도 기록한다.

검증 실패는 호출한 모드에서 처리한다. 모드 2는 이미 생성된 Pattern이라면
`passed=False`와 실패 사유를 기록한다. Pattern 생성 전 오류는 케이스 실패 목록에 기록한다.
벤치마크는 두 구현의 점수와 시간을 지역 변수에 보관한다. 판정과 PASS/FAIL은 `evaluate_pattern()`이 기록한다.

### 측정 범위

- 검증과 측정용 데이터 준비를 먼저 완료한다.
- 각 조합에서 2차원과 1차원 구현을 따로 측정한다. 방식마다 `time.perf_counter()`로 MAC 함수 R회 호출 구간을 재고, 조합별 평균을 `(끝 - 시작) * 1000 / R` ms로 계산한다.
  측정 구간에는 MAC 호출과 반복문 비용이 포함되며, 호출마다 타이머를 읽지 않는다.
- 입력·출력·파일 읽기·정규화·검증·배열 펼치기·점수 비교는 측정에서 제외한다.
- 모드 1은 3×3, 모드 2는 3×3·5×5·13×13·25×25를 측정한다.
- 모드 1은 입력 패턴과 A/B를 모두 측정한다.
- 모드 2는 추가 크기를 포함해 각 크기의 모든 유효 패턴과 Cross/X를 각각 측정한다.
- 최소 반복 횟수는 각 패턴·필터 조합마다 10회다.
  유효 패턴 P개와 반복 횟수 R에 대해 크기별 호출 수는 방식마다 `P × 2 × R`이다.
- 조합별 측정 구간의 경과 시간 합을 총 호출 수로 나누어 호출당 평균 ms를 출력한다.
  표의 연산 횟수는 호출당 N²이며, 두 필터 판정 전체나 반복 전체의 횟수와 구분한다.
- 평균 ms는 모든 행에서 소수점 이하 6자리로 출력한다.
- 제공 JSON에 없는 3×3은 고정 측정용 배열을 사용한다. 교체한 JSON에 유효한 3×3 케이스가 있으면 그 입력을 측정한다.
- 특정 크기에 유효한 조합이 있으면 검증 오류 케이스를 제외하고 해당 조합을 모두 측정한다.
- 필수 네 크기 중 유효한 조합이 전혀 없는 크기는 별도의 유효한 고정 패턴과 두 필터를 사용하며,
  대체 데이터를 사용했다는 사실을 출력한다.
  expected 라벨까지 검증을 통과한 뒤 동점이나 expected 불일치로 FAIL인 케이스는 점수를 출력하고 측정에도 포함한다.
  expected 누락·미지원 라벨 등 검증 오류 케이스는 점수와 측정에서 제외하고 ID와 실패 사유를 출력한다.
  계산 overflow로 판정하지 못한 케이스도 측정에서 제외한다.

## 모드별 흐름

### main.py

1. 모드 선택 메뉴를 표시한다.
2. 잘못된 선택은 안내 후 다시 받는다.
3. 선택에 따라 `mode1.main()`, `mode2.main()`, `bonus.main()` 중 하나를 호출한다.
4. `mode2.main()`이 파일 전체 오류로 `False`를 반환하면 반복문의 처음으로 돌아가 메뉴를 다시 표시한다.
   모드 2에서 `main.py`의 진입점을 재귀 호출하지 않는다.
5. 선택한 모드가 정상 완료되면 프로그램을 종료한다.
6. EOF 또는 Ctrl+C는 최상위 진입점에서 종료 안내와 함께 처리한다.

### mode1.py

1. 필터 A/B를 행 단위로 입력받고 검증한 뒤 Filter를 생성한다.
   각 배열은 3줄로 입력받는다. 각 행의 빈 줄은 오류이며, 3줄 뒤에 별도의 종료용 빈 줄을 요구하지 않는다.
   오류가 있으면 현재 필터의 임시 입력 전체를 비우고 3줄을 다시 받는다.
   앞서 정상 저장한 다른 필터는 유지한다.
2. 필터 저장 완료를 안내한다.
3. 패턴을 입력받고 검증한 뒤 expected 없이 Pattern을 생성한다.
   패턴의 첫 행에 Cross/X 이름을 입력하면 `generate_patterns(3)`에서 해당 배열을 가져온다.
   오류가 있으면 두 필터는 유지하고 패턴의 3줄만 다시 받는다.
4. `evaluate_pattern()`을 호출한다.
5. Pattern의 점수와 판정을 출력한다. expected 비교와 PASS/FAIL은 출력하지 않는다.
6. 입력된 패턴과 A/B 각각을 최소 10회 측정하고, 호출당 평균 ms와 N²를 출력한다.
   계산 범위 오류는 안내 후 두 필터를 유지하고 패턴 전체를 다시 입력받는다.

### mode2.py

1. `data/data.json`을 읽고 최상위 구조를 확인한다.
   경로는 `src/mode2.py` 위치에서 저장소 루트를 찾아 구성하므로 현재 작업 디렉터리에 의존하지 않는다.
   파일이 없거나 읽기·JSON 문법 오류가 있으면 원인과 경로를 출력하고 `False`를 반환한다.
   최상위 값이 객체가 아니거나 `patterns`가 없거나 딕셔너리가 아닌 경우에도 오류 안내 후 `False`를 반환한다.
   이 경우 케이스 분석·성능 측정·집계는 진행하지 않는다.
2. 크기별 필터를 검증·정규화해 저장한다. 잘못된 필터 그룹은 크기별 실패 사유를 따로 보관한다.
   예: `filters.size_5`가 객체가 아니거나, `cross`/`x`가 없거나, 필터 배열의 구조·크기가 잘못된 경우다.
   한 그룹의 오류는 해당 크기에만 적용하고 다른 크기의 필터 로드를 계속한다.
3. 원본 patterns 항목을 하나씩 처리한다.
   - 키에서 N을 추출하고 input과 expected를 검증한다.
   - expected를 정규화하고 Pattern을 생성한다.
   - N에 맞는 두 필터로 `evaluate_pattern()`을 호출한다.
   - Pattern에 저장된 결과를 출력하고 전체·통과·실패 수에 반영한다.
   - 케이스 값이 객체가 아니거나 키·input·expected 검증에 실패하면 ID와 사유를 출력·기록하고 다음 케이스로 진행한다.
     expected 검증 실패는 MAC 계산과 측정을 하지 않는다. 정상 라벨과 비교한 뒤 동점·불일치로 FAIL이면 점수와 측정은 유지한다.
4. 필수 네 크기와 추가 크기의 모든 유효 패턴·필터 조합을 측정하고 크기별 호출당 평균 표를 출력한다.
5. 전체·통과·실패 수와 실패 ID·사유 목록을 출력하고 `True`를 반환한다.

원본 케이스마다 한 번만 집계하며, Pattern 생성 실패나 필터 오류도 해당 케이스의 FAIL에 포함한다.
성능 측정은 테스트 수에 포함하지 않는다.

### 보너스 패턴 생성과 재사용

`patterns.generate_patterns(n)`은 Cross와 X의 독립적인 2차원 리스트를 반환한다. 모드 1의 패턴 선택, JSON 모드의 고정 측정 데이터, 모드 3이 이 함수를 공유한다. 모드 3은 두 배열을 각각 입력 패턴과 기준 필터로 사용해 네 조합을 비교한다. 콘솔에서는 생성 비용을 고려해 N을 1~512로 제한하고, N이 15 이하일 때 두 행렬 전체를 출력한다.

## 오류 처리 경계

| 오류 또는 결과 | 처리 위치와 동작 |
| --- | --- |
| 수동 입력의 숫자·행·열 오류 | 현재 필터 또는 패턴의 3×3 전체를 다시 입력. 다른 정상 입력은 유지 |
| JSON 파일 없음·읽기 실패·문법 오류 | 모드 2에서 안내하고 `False` 반환. main의 모드 선택 화면으로 복귀 |
| 최상위 값이 객체가 아니거나 `patterns` 누락·타입 오류 | 케이스 목록을 만들 수 없으므로 안내 후 모드 선택 화면으로 복귀 |
| `filters` 누락 또는 잘못된 구조 | 케이스 목록이 유효하면 각 케이스를 필터 오류 FAIL로 집계 |
| 특정 크기의 필터 그룹 타입·키·배열·크기 오류 | 그룹 단위로 `ValueError` 포착. 해당 크기를 사용하는 케이스만 FAIL. 다른 크기는 계속 처리 |
| 개별 케이스 객체·키·배열·expected 오류 | 케이스 단위로 `ValueError` 포착. 해당 케이스 FAIL과 사유 출력·기록 후 계속 처리. 점수·측정에서 제외 |
| 유한수 입력의 MAC 곱셈·누적 범위 오류 | `ValueError`로 전달. 모드 1은 패턴 재입력, 모드 2는 해당 케이스 FAIL 후 계속 처리. 점수·측정에서 제외 |
| 정상 계산 후 동점·expected 불일치 | 예외로 처리하지 않고 Pattern의 판정·비교 결과에 기록. 점수 출력과 성능 측정에 포함 |

## 확정된 실행 정책

- 한 필터만 대표로 고르지 않고 두 필터를 모두 측정한다. JSON은 모든 유효 패턴을 포함한다.
- 입력 오류는 현재 필터·패턴 전체를 다시 입력받으며, 정상 입력은 유지한다.
- 파일 전체 오류는 안내 후 모드 선택으로 복귀하고, 개별 케이스 오류는 FAIL 후 계속 진행한다.
